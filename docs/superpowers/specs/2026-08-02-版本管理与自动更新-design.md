# 版本管理与自动更新 — 设计文档

日期：2026-08-02
状态：已批准（用户确认：公开仓库 + 自动更新 + csproj 单一版本源，设计确定后直接实施）

## 背景与目标

1. 将项目推送到 GitHub 进行版本管理。
2. 应用内通过 GitHub 检查新版本，支持自动下载、替换并重启完成升级。
3. 每次发布新版本时产出 `bin\Release\SerialPort.exe` 作为发布产物。

## 约束

- .NET Framework 4.8.1，旧式 MSBuild 工程，无 NuGet 依赖——更新检查只能使用框架自带程序集。
- GitHub 仓库为**公开仓库**：任何用户可匿名访问 Releases API。
- 所有注释与界面字符串为中文。

## 方案选型

- **数据源：GitHub Releases API**（`GET https://api.github.com/repos/{owner}/{repo}/releases/latest`）。
  发布即"打 tag + 上传产物 + 写更新说明"一次完成；匿名限流 60 次/小时对个人工具足够。
  JSON 解析用 `DataContractJsonSerializer`（`System.Runtime.Serialization`，框架自带）。
- **版本号：csproj 单一版本源**。根 PropertyGroup 中 `<Version>x.y.z</Version>`，
  BeforeBuild target 用 `WriteCodeFragment` 生成 `obj\VersionInfo.cs`
  （`AssemblyVersion` / `AssemblyFileVersion` / `AssemblyInformationalVersion`）。
  删除 `Properties\AssemblyInfo.cs` 中硬编码的版本行，避免重复定义。
- **升级流程：应用内自动下载 + 替换 + 重启**（用户确认弹窗后执行）。

## 架构

### 新增 `Services\UpdateService.cs`

sealed 类，与 `SerialPortService` 完全一致的线程编组模式：
构造函数捕获 `SynchronizationContext.Current`，所有事件通过 `_syncContext.Post` 编组回 UI 线程。

公共 API：
- `void CheckForUpdatesAsync()` —— 后台线程 GET releases/latest，解析 `tag_name`（去 `v` 前缀）与当前程序集版本比较。
- `void DownloadAndApplyAsync()` —— 下载 + SHA256 校验 + 替换 + 重启。

事件：
- `CheckCompleted(object sender, UpdateCheckEventArgs e)` —— 携带：当前版本、最新版本（可空）、更新说明（`body`）、是否可更新、下载地址。
- `UpdateProgress(object sender, UpdateProgressEventArgs e)` —— 下载进度。
- `UpdateError(object sender, UpdateErrorEventArgs e)` —— 失败原因（网络失败 / 校验失败 / 替换失败）。

数据模型（DataContract 序列化类）：
- `ReleaseInfo`：`tag_name`、`body`、`assets[]`
- `ReleaseAsset`：`name`、`browser_download_url`

### 替换与重启时序

1. 下载 `SerialPort.exe` 与 `SerialPort.exe.sha256` 到 `%TEMP%\SerialPortUpdate\`。
2. 读取 .sha256 校验 exe，不一致则中止并报错。
3. `File.Move(SerialPort.exe, SerialPort.exe.old)` —— Windows 允许重命名运行中的 exe（映像以 FILE_SHARE_DELETE 打开）。
4. `File.Move(新exe, SerialPort.exe)`；若发布包含 `SerialPort.exe.config` 同样替换。
5. `Process.Start(SerialPort.exe)` 启动新进程。
6. `Application.Current.Shutdown()` 退出旧进程。
7. 步骤 4 抛异常时回滚：`File.Move(SerialPort.exe.old, SerialPort.exe)`，应用继续运行。

- 状态栏新增"检查更新"入口（文本按钮）与状态显示（"已是最新版本 v1.0.0" / "发现新版本 v1.0.1" / "检查更新失败"）。

## 发布流程（写入 README）

1. 修改 csproj `<Version>` 为新版本号。
2. `MSBuild.exe SerialPort.csproj /p:Configuration=Release` 构建。
3. `git add/commit`，`git tag vX.Y.Z`，`git push --tags`。
4. GitHub 网页创建 Release：选 tag，写更新说明，上传 `bin\Release\SerialPort.exe`、
   `bin\Release\SerialPort.exe.config`，并用 `certutil -hashfile` 生成 `SerialPort.exe.sha256` 一并上传。

## 错误处理

| 场景 | 行为 |
|------|------|
| 网络失败 / 超时 / 403 限流 | 状态栏显示"检查更新失败"；手动检查时弹提示 |
| 下载中断 | 删除临时文件，可重新下载 |
| SHA256 校验失败 | 中止，报错，不替换任何文件 |
| 替换失败 | 回滚 .old，应用继续运行 |
| 更新期间用户点"稍后" | 取消流程，不做任何修改 |
