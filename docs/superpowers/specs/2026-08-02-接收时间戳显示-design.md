# 接收区时间戳显示 — 设计文档

日期：2026-08-02
状态：已批准（用户确认：按完整行打时间戳 + 行首实时显示 + 保存文件也带时间戳）

## 背景与目标

在"16进制发送"复选框左侧新增"时间戳显示"复选框。勾选后，接收窗口中每收到一**行**串口数据，行首显示该行收到时的时分秒（格式 `[HH:mm:ss] `），便于追溯每条数据的到达时间。

## 用户确认的需求决策

1. **时间戳粒度：按完整行**。每行一个时间戳，同一行的数据不重复加戳。
2. **半行（无换行结尾）数据：行首实时显示**。新行开始时先写时间戳，数据实时追加，遇到换行符才终结该行——时间戳标记该行开始收到的时刻，无显示延迟。
3. **保存文件也带时间戳**：文件保存写入与接收窗口完全相同的文本。

## 约束

- .NET Framework 4.8.1，无 NuGet 依赖。
- 遵循现有"增量追加"性能模式：不得整体重赋 `txtReceive.Text`。
- 所有注释与界面字符串为中文。

## 方案选型

**MainWindow 层状态机加戳**（方案 A，推荐）：

- 在 `MainWindow.OnDataReceived` 中对增量文本做"行首补时间戳"变换，变换后的文本统一流向显示 / 筛选缓冲 / 保存文件。
- `[HH:mm:ss]` 前缀是显示关注点，归 UI 层；服务层（`SerialPortService`）不理解显示格式，不改动事件契约。
- 与现有 AppendText 增量追加模式兼容，无性能回退。

（备选 B 服务层加戳——职责混淆且改动事件契约，不采用；备选 C 附加行为/自定义控件——过度设计，不采用。）

## 架构

### 界面（MainWindow.xaml）

配置区行2 的 StackPanel 中，"打开串口"按钮（`btnToggleConnect`）与"16进制发送"（`chkSendHex`）之间插入：

```xml
<CheckBox x:Name="chkTimestamp" Content="时间戳显示" Margin="0,0,18,0" VerticalAlignment="Center" />
```

### 加戳机制（MainWindow.xaml.cs）

新增私有方法 `GetTimestampedText(string increment)`，输入单次接收的增量文本，输出加戳后的文本。

用一个跨调用私有状态字段维护"行首"位置：

- `_atLineStart`（bool，初始 `true`）：当前是否处于行首。

换行判定复用既有 `NewLineChars` 常量（`IndexOfAny` 快速扫描）与共享谓词 `IsNewLineChar(char)`，不重复硬编码换行字面量。

逐字符扫描算法（`\n` 本身永远不补戳，故换行后立即置行首位即等效于"区分 `\r\n` 与单独 `\r`"，无需额外状态）：

```
对每个字符 c：
  若处于行首且 c 不是换行符（\r、\n）：先写 [HH:mm:ss]（同一数据块共享一个 DateTime.Now），再写 c
  写 c
  若 c 是换行符（\r 或 \n）：进入行首
```

未勾选时间戳时，跳过输出构造，仅用 `increment.IndexOfAny(NewLineChars)` 跟踪行首位置后直接返回原文（零分配）。

行为保证：

- `\n`、`\r`、`\r\n` 三种换行都正确终结一行；`\r\n` 跨块拆分（前块末尾 `\r`、后块开头 `\n`）不产生错误时间戳。
- 空行（如连续 `\r\n`）不产生时间戳。
- 无换行结尾的半行数据实时显示，时间戳标记行首收到的时刻。
- 十六进制模式下每块即一行（`GetIncrementText` 每块 `AppendLine()`），等价于每块一个时间戳。
- 中途勾选/取消勾选不影响状态机，只影响之后新开始的行。

状态机**始终运行**（无论复选框是否勾选），仅当勾选时输出时间戳前缀——这样中途切换时行首状态始终准确：取消勾选期间收到的数据照常推进行首位置，重新勾选后，未结束的当前行不会错误地补时间戳，下一行才恢复加戳。

### 数据流（OnDataReceived）

勾选"时间戳显示"时，先把 `increment` 替换为 `GetTimestampedText(increment)`，其余路由不变：

```
increment ──加戳──► 显示（AppendText / AppendFiltered）
              ├──► 筛选缓冲（_filterState.Buffer）
              └──► 保存文件（_saveFileWriter）
```

显示、筛选、保存文件三处拿到同一份加戳文本，保持一致。

### 时间戳取值

`DateTime.Now`，在 UI 线程渲染时刻取（事件已由 `_syncContext.Post` 编组回 UI 线程）。与后台读线程的偏差为毫秒级，对调试用途足够；不做读取时刻精度改造（那需要改动服务层事件契约，超出本需求范围）。

## 错误处理与测试

- 纯显示变换，无新增错误路径、无 I/O 或网络操作。
- 项目无测试框架；实现后由开发者构建并运行验证：
  1. 勾选时间戳后，文本模式整行/半行/跨块数据的时间戳正确；
  2. 十六进制模式每块一个时间戳；
  3. 文件保存内容与窗口一致（均带时间戳）；
  4. 筛选启用时行为正常。
